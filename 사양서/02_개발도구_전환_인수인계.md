# 사양서 02 — 개발 도구 전환 시 맥락·일관성 유지 (인수인계 장치)

> 2026-10-10 설계 · 작성 Claude(Sonnet) · **구현 완료 0.42**(결정 10장: 1=A 시험 자동 실행 켬, 2=A Git 체크포인트 — 사용자 위임) · 확신도: 중간(실제 Claude Code·Codex 실행 시험 전)
> **구현이 설계와 다른 점**: ① 체크포인트는 임시 브랜치 커밋이 아니라 `refs/jeeves/<작업>/<순번>`(작업 브랜치·폴더·색인을 안 바꿈) ② 시험 퇴보는 통과→실패만 감지 ③ LOCK은 지브스가 실행한 작업끼리만(터미널에서 따로 켠 AI는 감지 불가) ④ 구문 점검은 js·json만 ⑤ 되돌리기 단추·화면 표시는 후속
> 대상 코드: `jeeves-app\src\main\dev-chain.js`(진행자), `dev-engine.js`(실행·폴더 비교), `dev-team.js`(.jeeves 계획 파일). 기준서 2장(헌장)·7장(보안)·8장 준수.

## 1. 지금 문제 (사실: 코드 확인)

- 엔진을 넘길 때 다음 엔진이 받는 것은 목표 원문 + "[이어서 진행] 앞서 ○○가 ○○로 중단됐습니다. 폴더 상태를 확인하고 이어서 하세요" **한 문장**뿐입니다(`dev-chain.js` 21행).
- 그래서 다음 엔진이 폴더를 처음부터 다시 훑어 알아내야 하고, 이것이 **토큰을 가장 많이 쓰는 부분**이며 오해(이미 된 일을 다시 만들기, 다른 방식으로 만들기)의 원인입니다.
- 이미 코드가 계산하는데 버리는 정보: 바뀐 파일 목록(`diffSnap`), 시도한 엔진·결과 종류, 한도 풀리는 시각.

## 2. 원칙 (핵심 한 줄)

**인수인계서는 AI가 아니라 지브스 코드가 만든다(토큰 0). 다음 엔진은 그 파일 하나만 읽는다(약 600토큰 이하).** 엔진 종류(Claude Code·Codex·기타)에 상관없이 같은 파일을 쓰므로 어떤 순서(6가지 이상)로 바뀌어도 동작이 같다.

## 3. 만드는 것 (프로젝트 폴더의 `.jeeves\`, 이미 팀 작업이 쓰는 폴더)

| 파일 | 만드는 쪽 | 내용 | 토큰 |
|---|---|---|---|
| `HANDOFF.md` | **코드**(전환·종료 때마다 덮어씀) | 아래 4장 | 0 (읽는 쪽만 ~600) |
| `LEDGER.jsonl` | 코드(한 줄 추가만) | 엔진·난이도·시작/끝·결과 종류·바뀐 파일 수·시험 결과·비용 추정 | 0, 엔진이 읽지 않음(사람·지브스 화면용) |
| `CONTEXT.md` | 사용자 또는 첫 엔진 1회 | 프로젝트 고정 정보: 목적·기술·폴더 구조·코딩 규칙·**결정 사항(왜 그렇게 했나)** — 잘 안 변하는 것 | 1회 작성, 이후 필요할 때만 읽음 |
| `checkpoints\` | 코드 | Git 폴더면 체크포인트 커밋, 아니면 파일 해시 목록 | 0 |
| `LOCK` | 코드 | 지금 쓰는 엔진 id·시작 시각(동시 실행 방지) | 0 |

- 엔진마다 읽는 규칙 파일이 달라(Claude Code=`CLAUDE.md`, Codex=`AGENTS.md`) 서로 다르게 동작하는 것이 일관성의 가장 큰 위험입니다. **사용자 프로젝트의 두 파일은 건드리지 않고**, 지브스가 프롬프트 맨 앞에 짧은 고정 안내(150토큰 이내)를 붙입니다: "`.jeeves\HANDOFF.md`를 먼저 읽고, `.jeeves\CONTEXT.md`의 규칙·결정을 따르고, 끝나면 아래 3줄로 보고". 이 문구는 모든 엔진 공통입니다(기존 `RULES` 상수 방식 확장).
- 이 저장소(지브스 자체)처럼 이미 `CLAUDE.md`·`AGENTS.md`·03 인수인계 로그가 있는 프로젝트는 그 규칙이 우선이고, `HANDOFF.md`는 그 위에 "이번 지브스 작업 한정 상태"만 더합니다. 규칙이 충돌하면 기준서 우선.

## 4. HANDOFF.md 내용 (코드가 채움, 2,000자 상한, 넘으면 오래된 시도부터 한 줄 요약)

1. **목표 원문**과 **완료 조건(done_when)** — 번역·요약 없이 그대로(헌장·기준서 6장 티켓 원칙).
2. **시도 이력 표**: 순번 · 엔진(모델) · 난이도 · 결과(성공/한도/로그인/실행불가/작업실패/중단) · 종료 시각 · 한도 풀리는 시각.
3. **지금 폴더 상태**: 추가·수정·삭제된 파일 목록(`diffSnap` 결과, 최대 40개, 넘으면 개수만), Git이면 `git status --short` 요약. **파일 내용·diff 본문은 넣지 않음**(필요하면 엔진이 직접 열게 해 토큰 절약).
4. **자동 점검 결과**(코드가 실행): ① 시험 명령(`package.json`의 `test` 등, 설정에 없으면 건너뜀) 통과/실패와 **실패한 항목 이름만** ② 구문 점검(`.js`→`node --check`, `.json`→`JSON.parse`, `.py`→`py_compile`)에서 **깨진 파일 목록**(엔진이 쓰는 도중 한도로 끊긴 경우 대비).
5. **이전 엔진이 직접 남긴 3줄 보고**(있으면): `한 일 / 남은 일 / 주의`. 없으면 "보고 없음(중단됨)" — 그래도 3·4번이 있어 이어갈 수 있음.
6. **정보 등급**: 이번 작업 등급. 등급 관문을 통과한 엔진에만 이 파일이 전달됨(C 내용이 낮은 등급 엔진으로 새는 것 방지, 기준서 7장).
7. **다음 엔진에게 줄 지시(고정 문구)**: "이미 된 파일은 다시 만들지 말 것 / 깨진 파일·실패한 시험부터 고칠 것 / 범위 밖 파일은 건드리지 말 것 / 새 결정을 내렸으면 `CONTEXT.md`의 '결정' 줄에 추가".

## 5. 전환 절차 (모두 코드, AI 호출 없음)

```
엔진 A 끝남(성공·한도·로그인·실패 어느 경우든)
 ① A가 쓰던 프로세스 종료 확인 → LOCK 해제
 ② 폴더 비교(diffSnap) + 구문 점검 + 시험 실행(있을 때만)        ← 토큰 0
 ③ 체크포인트 저장: Git이면 'jeeves/<작업ID>' 브랜치에 임시 커밋, 아니면 해시 목록
 ④ HANDOFF.md·LEDGER.jsonl 갱신
 ⑤ 다음 엔진 B 선택(기존 DevRouter 규칙: 등급 관문 → 비용 → 난이도 → 쉬는 중 제외)
 ⑥ LOCK 잡고 B 실행 (프롬프트 = 공통 안내 150토큰 + 목표 원문)
 ⑦ B가 HANDOFF.md를 읽고 이어서 진행
```

- **일관성 보호 장치**
  - **한 번에 한 엔진만**(LOCK). LOCK은 지브스가 실행한 작업끼리만 막는다(사용자가 터미널에서 따로 켠 AI는 지브스가 알 수 없음 — 한 번에 한 AI만 쓰는 것은 사용자 규칙).
  - **회귀 방지**: 엔진이 바꾼 뒤 시험 통과 건수가 전보다 줄었으면 HANDOFF 맨 위에 "⚠ 시험 퇴보 — 먼저 복구" 표시. **자동으로 되돌리지는 않음**(사용자 파일을 AI·코드가 임의로 되돌리면 위험) — 화면에 "체크포인트로 되돌리기" 단추만 제공(사용자 승인, R2).
  - **깨진 파일 우선 복구**: 구문 오류가 있으면 새 일보다 먼저 고치게 지시.
  - **결정 기록**: 엔진이 새 구조·라이브러리를 정하면 `CONTEXT.md` '결정' 줄에 한 줄(이유 포함). 다음 엔진이 다른 방식으로 뒤집지 않게 함.
  - **비밀 보호**: HANDOFF·LEDGER·CONTEXT에 키·비밀번호·계정 파일 내용을 쓰지 않음(기록 전 정규식 검사로 제거, 기준서 7장).

## 6. 엔진 순서가 달라도 같은 동작인 이유 (사용자 요청 조합 점검)

| 순서 예 | 전환 때 달라지는 것 | 처리 |
|---|---|---|
| Claude Code → Codex → 기타 | 실행 옵션·권한 문법·사용 규칙 파일 | 어댑터(`buildCommand`)가 흡수, 인수 내용은 동일한 HANDOFF.md |
| Codex → Claude Code → 기타 | Claude는 `CLAUDE.md`를 자동으로 읽음 | 프로젝트 파일은 그대로, 공통 안내가 HANDOFF를 가리킴 |
| Claude Code → 기타 → Codex | 기타 AI는 도구·문맥 능력이 약할 수 있음 | 난이도 한도(`maxLevel`)로 제외, 약한 엔진은 HANDOFF의 "남은 일"만 크게 보여 줌 |
| 기타 → Claude Code → Codex … | 기타 AI가 보고를 안 남길 수 있음 | 보고 없어도 3·4번(코드가 만든 사실)으로 이어감 |

- 같은 엔진이 두 번 나오는 경우(예: Claude → Codex → Claude)도 동일하게 HANDOFF를 새로 만들어 줌. 한도로 쉬는 엔진은 풀리는 시각 전까지 순서에서 제외(기존 규칙).

## 8. 시험 계획 (가짜 엔진으로, 실제 계정·토큰 사용 없음)

1. 가짜 엔진 3종으로 **순서·횟수가 정해져 있지 않다는 전제**의 시험: 3종 순열 6가지 + 같은 종류 반복·길이 2~8 무작위 40가지(시드 고정) + 9단 전환. 매 전환마다 공통 안내·목표 원문 보존, 이전 시도 이력 누적, 앞선 엔진이 남긴 파일 목록 정확, LOCK 해제, 장부 줄 수.
2. 엔진이 파일 쓰는 도중 끊긴 상황: 깨진 JSON·JS 감지.
3. 시험 퇴보 감지 표시, 자동 되돌리기 없음 확인.
4. 비밀 문자열이 HANDOFF·LEDGER에 안 들어감.
5. LOCK: 이미 실행 중이면 두 번째 시작 거부.
6. 정보 등급: 등급이 낮은 엔진에는 C 작업 인수인계 미전달.
7. 2,000자 상한·오래된 이력 요약.
8. 기존 `dev-tests`·`team-tests`·`junior-tests` 전부 통과 유지(기준선 이상).

## 9. 구현 배정 (CLAUDE.md 규칙, 한도 임박 반영)

- **D2** `jv-builder`(Sonnet) 2명 동시: ① `handoff.js`(HANDOFF·LEDGER·CONTEXT 생성, 구문·시험 점검, 비밀 제거, 상한) ② `dev-chain.js` 연결 + LOCK + 공통 안내 + 체크포인트(같은 파일을 만지므로 ①과 순서: ① 완료 후 ②).
- **D1** `jv-runner`(Haiku): 전체 시험. **D2-검수** `jv-reviewer`: 보안(비밀·LOCK·되돌리기).
- Claude 한도가 부족하면 구현은 **Codex가 `AGENTS.md` 규칙으로** 이어받을 수 있음(이 사양서가 설계 근거, 03 인수인계 로그 갱신 후 교대).
- 예상 규모: 새 파일 1개(약 250줄) + 기존 파일 수정 2~3개, 시험 8항목.

## 10. 사용자 결정 필요 (2지선다)

1. **시험 명령 자동 실행**: A) 켬(추천) — 엔진 전환 때마다 `npm test` 등을 코드가 실행(토큰 0, 시간만 듦) / B) 끔 — 구문 점검과 파일 목록만.
2. **체크포인트 방식**: A) Git 폴더면 `jeeves/<작업ID>` 임시 브랜치에 커밋(추천, 되돌리기 쉬움, 단 사용자 저장소에 브랜치가 생김) / B) 해시 목록만(저장소 안 건드림, 되돌리기는 불가·비교만).

## 11. 한계·[확인 필요]
