# 사양서 03. 개발 AI 자동 선정과 자동 착수·재개

> 기준서 0.44 · 2026-10-10 · 모든 판단은 규칙(코드)이며 AI 호출·토큰이 들지 않습니다.

## 1. 한 줄 요약
지시를 보내면 지브스가 **난이도 · 분량 · 지금의 여유**를 보고 Claude Code / Codex / 기타 도구의 순서를 정해 착수하고, 한도로 멈추면 **풀리는 시각에 스스로 다시 고른 뒤 이어서** 진행합니다. 앱을 껐다 켜도 이어집니다.

## 2. 판단 재료 (`src/dev/dev-capacity.js`)
| 재료 | 읽는 법 | 믿는 정도 |
|---|---|---|
| 난이도 L1~4 | 기존 `analyzeDifficulty` | 기존과 동일 |
| 분량 1~4 (작음~매우 큼) | 요구 항목 수, "N개 화면·기능", 전체/모든, 연결어 개수, 설명 길이, 첨부 수·시안, 기존 파일 수. 좁은 수정(오타·문구)은 감점 | 규칙 추정 — 화면에 근거를 그대로 표시 |
| 여유 (계열별: claude / codex) | ① 한도에 실제 닿은 기록(풀리는 시각 포함) ② 최근 24시간 한도 횟수(1회=빠듯, 2회=부족) ③ 사용자가 입력한 사용량 %(75%↑ 빠듯, 90%↑ 부족, **48시간 지나면 무시**) | ①②는 자동·확실, ③은 수동 |

**하지 않는 것**: 구독 잔여량을 프로그램이 읽는 방법은 확인되지 않았습니다(기준서 12장). 그래서 잔여량을 추측해 표시하지 않고, 정보가 없으면 "정보 없음(보통으로 봄)"으로 둡니다.

## 3. 선정 규칙 (`DevRouter.plan`)
1. 정보 등급·설치·쉬는 중 통과 → 2. **한도에 닿은 계열은 제외**(풀리는 시각 표시) → 3. 비용(무료<구독<API) → 4. "Codex 먼저/Claude 먼저" 설정 → 5. **여유 감점**(필요 여유 = 난이도×분량: 작음/중간/큼. 작은 일은 빠듯해도 그대로, 중간·큰 일은 빠듯한 계열을 뒤로) → 6. 로컬 → 7. 난이도를 겨우 채우는 약한 엔진 → 8. 우선순위 → 9. 덜 쓴 쪽.
- 분량이 "큼" 이상이면 난이도가 낮아도 **L3 이상으로** 봅니다(작은 모델에 통째로 맡기지 않음).
- 같은 계열 한도: Claude Code 한 모델이 한도에 닿으면 같은 구독의 다른 모델도 쉬게 합니다. Codex도 같습니다. 주니어·기타 도구는 각자 따로 [추정: 모델별 별도 한도가 있는 요금제는 이 가정보다 보수적임].

## 4. 자동 착수 · 재개 (`main.js` 작업 보관소)
- 시작: 계획 카드에 분량·여유·순서가 보입니다. 모든 계열이 한도이고 풀리는 시각을 알면(12시간 이내) **"예약 시작"** → 그 시각 +1분에 자동 착수.
- 멈춤: 모든 엔진이 한도로 끝나면 완료 처리하지 않고 **대기**합니다(카드에 "⏳ …에 자동 재개"). 폴더 잠금은 유지됩니다.
- 재개: 시각이 되면 **여유를 다시 보고 엔진을 다시 고른 뒤**, 같은 지시에 "[이어서 진행]"을 붙여 `.jeeves/HANDOFF.md` 기준으로 남은 일부터 진행합니다. 한도가 반복되면 최대 6회까지.
- 중지: 대기 중에도 "중지"로 예약을 취소할 수 있습니다.
- 앱 재시작: 보관소(`jeeves-dev-pending.json`)에 지시문·폴더·상태만 저장(키·비밀 없음). 다시 켜면 예약은 복원, 시각이 지났거나 중간에 꺼진 작업은 설정에 따라 **자동으로 이어가기** 또는 **물어보기(이어서 진행 / 버리기)**.
- 팀 작업이 한도로 멈춘 경우 재개는 일반 연쇄로 진행하며 `.jeeves/PLAN.md·tasks.json` 이 있으면 남은 조각부터 하도록 지시합니다.

## 5. 설정 (5-2)
- 한도로 멈추면 자동 재개(기본 켬) / 앱을 껐다 켰을 때(자동·물어보기, 기본 자동)
- 사용량 % 입력(Claude·Codex, 선택). 값을 바꾼 때만 입력 시각을 새로 기록.

## 6. 시험
`tests\dev-capacity-tests.js`(분량·여유·순서·기록·연결), `tests\dev-jobs-tests.js`(대기·재개·중지·꺼짐 복원), `tests\ui-sim.js`(화면, jsdom).

## 7. 한계 [사실/추정 구분]
- [사실] 실제 PC에서 Claude Code·Codex 로 한도 도달 → 재개한 시험은 아직 하지 않았습니다(가짜 개발 AI 로만 확인).
- [추정] 한도 풀리는 시각은 Claude Code 출력의 시각 표기를 읽을 수 있을 때만 정확하고, 못 읽으면 30분 뒤 재시도합니다.
- 사용자 입력 사용량 %는 사용자가 적은 값일 뿐 프로그램이 검증하지 못합니다.
