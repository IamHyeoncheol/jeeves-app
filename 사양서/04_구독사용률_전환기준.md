# 사양서 04 — 구독 사용률 자동 읽기 · 전환 기준 % · 물어보기 카드

- 작성: Claude · 2026-10-10 · 담당: **Codex**(사용자 결정 A안 — Claude 7일 사용률 97%라 한도 보존)
- 목적: 한도에 "닿은 뒤" 전환하던 것을, 사용률을 미리 읽어 **정한 기준 %에서 묻거나 자동으로 넘기기**. 전환 기준 2번(예산 모드)의 바탕.
- 기준: 기준서 3장(근본 목적·완전 자동화 근접·2지선다), 5.5(예산 모드), 12장(구독 사용률 읽기 가능 — 확인됨 2026-10-10).
- 원칙: 전부 규칙 코드(AI 호출 0). 모르는 값은 지어내지 않는다("정보 없음" = 지금처럼 한도에 닿으면 전환).

## 0. 확인된 사실 [사실: 사용자 PC 실기 기록 2026-10-10]
Claude Code `--output-format stream-json` 출력에 이런 줄이 온다:
```json
{"type":"rate_limit_event","rate_limit_info":{"status":"allowed_warning","resetsAt":1791928800,"rateLimitType":"seven_day","utilization":0.97,"surpassedThreshold":0.75,
 "unifiedWindows":{"five_hour":{"utilization":0.67,"resetsAt":1791625200},"seven_day":{"utilization":0.97,"resetsAt":1791928800}}}}
```
- `utilization` 0~1, `resetsAt` 초 단위 유닉스 시각. 창은 `five_hour`·`seven_day`.
- Codex 출력에 같은 정보가 있는지는 **[확인 필요]** — 첫 Codex 실행 로그에서 찾아보고, 없으면 Codex는 "정보 없음"으로 둔다(지어내지 않음).

## 2. 전환 판정 (규칙, AI 0)
작업 시작 직전(개발 `devPlan`·구독 웹 작업·구독 대화)에 엔진 계열별로:
```
u = devCap.state(family).usedPct   (없으면 판정 생략 → 지금 동작 그대로)
rule = config.dev.switchRule[family]
u < rule.pct            → 그대로 진행
action === 'continue'   → 그대로 진행(카드 없음, 한도에 닿으면 기존 자동 전환)
action === 'switch'     → 그 계열을 이번 작업 엔진 목록에서 뒤로 미룸(다른 엔진이 없으면 그대로 진행), 화면에 "사용률 97%라 Codex로 넘겼습니다" 한 줄
action === 'ask'        → 카드(2지선다)
```
카드 문구:
> **Claude 사용률이 기준(90%)을 넘었습니다** — 7일 97% · 10월 14일(수) 07:00 초기화
> **A. 다른 엔진으로 넘기기(추천 · 남은 한도 보존)** — 이번에 쓸 엔진: Codex
> B. 한도까지 Claude 계속
> ☐ 이번 초기화 때까지 다시 묻지 않기
- **응답 없음(askTimeoutMin, 기본 5분) → A** (완전 자동화 원칙: 자리 비우면 싸고 안전한 쪽). 넘길 다른 엔진이 없으면 B로 진행하고 그 사실을 표시.
- 비상 정지 중이면 카드도 띄우지 않는다(기존 정지 판정이 먼저).
- 감사 기록 `kind:'action', action:'engine-switch', decision: 'auto'|'approved'|'timeout'` 1줄(사용률 숫자·계열만).

## 3. 시험 (가짜 데이터만)
1. `rate_limit_event` 줄 → `onUsage`로 pct 97·resetsAt ms 변환 정확
2. 자동 값이 사용자 입력 %보다 우선, `resetsAt` 지나면 자동 값 무시 → 사용자 입력 % → 둘 다 없으면 `source:'none'`
3. 판정표 4갈래(미만/continue/switch/ask) 각각, switch 인데 다른 엔진 없음 → 그대로 진행
4. ask 응답 A·B·무응답(→A)·"다시 묻지 않기"(같은 초기화 안에서 두 번째 작업은 카드 없이 A) · 초기화 지나면 다시 물음
5. config sanitize(pct 범위·action 값)
6. 정보 없음(Codex) → 판정 생략, 기존 동작과 같음(회귀)
7. 기존 `npm test` 전부 통과(현재 280건)

## 4. 완료 조건
- 위 시험 + 기존 시험 전부 통과, 커밋 메시지에 `작업 AI: Codex`
- 기준서 13장(0.50)·11장 체크, `03_다음대화_이어하기.md` 인수인계 로그 한 줄

# 2단계 (2026-10-10 추가 · 같은 담당 Codex) — 유료 AI별 한도·잔여량 설정과 알림

사용자 요청: "각 AI(유료 모델)에 대해 한도 잔여량을 설정하고 알려주는 기능". 1단계(구독 사용률·전환 기준)를 끝낸 뒤 이어서 한다.

## A. 대상과 잔여량을 아는 방법 (지어내지 않음)
| 대상 | 잔여량 계산 | 근거 |
|---|---|---|
| 구독: Claude Code | 자동: `rate_limit_event`의 5시간·7일 사용률 → 잔여 = 100 − 사용률(%) | 1단계 |
| 구독: Codex | 출력에 사용률이 있으면 자동, 없으면 **사용자가 입력한 사용률 %**(48시간 유효) | [확인 필요] |
| API 키 공급자(설정의 `tier:'paid'` 전부: Anthropic·OpenAI·xAI·OpenRouter·TypeSafe·GLM·Kimi·DeepSeek 등) | **사용자가 정한 예산(원)** − 비용 장부(`ledger`)의 그 공급자 실제 사용액. 기간: 월(1일 초기화, 기본) 또는 "충전 잔액"(사용자가 충전 금액·충전일 입력 → 그 이후 사용액 차감) | 비용 장부 `provider` 칸(0.49). 공급자 잔액을 API로 읽는 공식 방법은 [확인 필요] — 확인 전까지 읽지 않음 |
| 무료·로컬 | 대상 아님(표시만 "무료") | — |

- 비용 장부의 단가 모름(`usd:null`) 호출은 "잔여량 정확도 낮음" 표시 + 건수.
- 장부 금액은 단가표 추정치라 실제 청구와 다를 수 있다는 문구를 화면에 항상 표시.

## B. 설정 (`config.js` → `limits`)
```js
limits: {
  alertAt: [50, 80, 90],          // 남은 양이 아니라 "사용한 양 %" 기준 알림 단계
  providers: { anthropic: { mode: 'monthly'|'prepaid'|'off', budgetKrw: 0, prepaidAt: null } , ... },   // tier:'paid' 공급자만
  subscriptions: { claude: { manualPct: null, at: 0 }, codex: { manualPct: null, at: 0 } }   // 1단계 dev.capacity 입력과 같은 값이면 하나로 합칠 것(중복 금지)
}
```
sanitize: 예산 0~1억 원 정수, 모드 셋 중 하나, alertAt 1~100 오름차순 최대 5개.

## C. 계산 모듈 `src/policy/limits.js` (신규, 순수 함수 · Electron 없이 시험)
- `remaining({ config, ledgerSummaryByProvider, capacityState, now })` → 대상별 `{ id, label, kind:'api'|'subscription', usedPct, remainingText, resetsAt?, source:'auto'|'manual'|'budget'|'none', accuracy:'ok'|'low', level: 0|50|80|90|100 }`
- 비용 장부에 공급자별 합계가 필요하면 `ledger.summary()`에 `byProvider` 추가(기존 필드 유지).

## D. 알림 (규칙, AI 0)
- 단계(`alertAt`)를 **처음 넘는 순간 한 번만** 알림(같은 기간 안에서 같은 단계 반복 금지, 기록은 `jeeves-limits-state.json`).
- 알림 방법: 화면 위쪽 안내 줄(`router:notice` 재사용) + Windows 알림(기존 `notify`) — "OpenAI 이번 달 예산 80% 사용(남은 약 2,000원)".
- 100% 도달: API 공급자는 라우터에서 그 공급자를 "쉬는 중"(기존 `markCool`, 사유 '사용자 예산 소진', 기간 끝까지)으로 두어 **자동으로 다음 공급자로 넘김**. 구독은 1단계 전환 규칙을 따름.
- 감사 기록 `kind:'action', action:'limit-alert'` 1줄(대상·단계만).

## E. 화면
- 오른쪽 위(비상 정지 옆) 작은 **"한도" 단추** → 대상별 막대(사용 %·남은 양·초기화 시각·출처 auto/수동/예산), 80% 이상 주황, 90% 이상 빨강.
- 설정 5-1(공급자) 각 유료 공급자 줄에 "월 예산(원)·방식" 입력칸, 5-2(개발)에 구독 사용률 수동 입력(1단계와 공용).
- 새 화면 코드는 `src/ui/limits-ui.js`(app.js 키우지 않음).

## F. 시험 `tests/limits-tests.js`
1. 월 예산 10,000원·장부 8,000원 → 사용 80%, 남은 2,000원, level 80
2. 충전 방식: 충전일 이전 사용액은 빼지 않음
3. 단계 알림 한 번만(80% 두 번 넘어도 1회), 달이 바뀌면 다시 0부터
4. 100% → 라우터가 그 공급자를 건너뛰고 다음 공급자로 호출(가짜 fetch)
5. 구독 자동 값 > 수동 값 > 없음, 초기화 시각 지나면 자동 값 무시
6. 단가 모름 호출이 있으면 accuracy 'low'
7. 기존 시험 전부 통과

## G. 완료 조건
2단계 시험 + 전체 통과, 기준서 13장 0.51·3장 결정 행은 이미 있음(아래), 인수인계 로그, 사용자 PC 확인 항목: 한도 단추 표시, 예산을 작게(예: 100원) 잡아 알림·자동 넘김 확인.
