- 1단계 담당은 **기존 파일을 하나도 고치지 않는다** (package.json도 2단계 D2만 고친다). 시험은 `node tests/policy-xxx-tests.js`로 직접 실행.

### 1.4 수정 파일별 변경 (2단계)

**D1 — `src/agent/agent.js`** [사실: assessRisk :52, riskOf :234, guardedAction :275, log :153, stop :158, router.call :321·:423]
- `assessRisk(name, input, snap, confirmMode)`는 이름·시그니처 유지, 내부를 `toLegacy(classify({...}), confirmMode)`로 교체 (mcp-server와 기존 시험이 계속 사용). `RISKY_WORDS` export도 유지.
- `riskOf(name, input)` → `classify({ name, input, snap: this.driver.lastSnapshot, source: who, confirmMode, aiLevel: input.risk, opts: this.policy?.opts })` 결과(새 형식)를 반환.
- `guardedAction(name, input, who)` 흐름:
  1. `this.policy?.killSwitch?.halted` 이면 `{ cancelled: true }` 반환 + 감사 `decision:'halted'`.
  2. `isBlocked(risk)` → 실행 안 함, `log('blocked', …)`, AI에게 `"차단됨(R3): <why>. 이 행동은 사용자가 PC에서 직접 해야 합니다. ask_user 로 요청하세요."` 반환.
  3. `needsApproval(risk)` 또는 confirmMode always → `waitForUser('confirm', { desc, why, level })` (UI가 등급 배지를 보여 줄 수 있게 `level` 추가). 거절 → 지금과 같음. `cancelled` → 지금과 같음.
  4. R0/R1 → 바로 실행.
  5. 모든 분기에서 `this.policy?.audit?.write({...})` 1회 (5장 형식). 기존 `log()`는 그대로 둔다(UI 표시용).
- `TOOLS`의 `navigate, click, type_text, select_option, press_key` 입력 스키마에 선택 항목 추가: `risk: { type:'string', enum:['R0','R1','R2','R3'], description:'더 위험하다고 판단되면 올려서 표시(낮출 수 없음)' }`. 시스템 프롬프트 안전 규칙에 한 줄 추가: "되돌릴 수 없을 것 같은 행동은 risk 를 R2 이상으로 표시하세요."
- `router.call(...)` 두 곳에 `meta: { taskId: this.id, source: 'jev' | this.role }` 추가.
- `stop()`은 변경 없음.

**D1 — `src/main/mcp-server.js`** [사실: act() :61~85, assessRisk 사용 :67]
- `act(name, input, run)` 첫 줄: `this.d.policy?.killSwitch?.halted` 이면 실행하지 않고 `observe('비상 정지 중입니다. 사용자가 PC 화면에서 재개하기 전에는 아무 행동도 할 수 없습니다.')` 반환.
- 판정을 `classify({ ..., source:'mcp', aiLevel: input.risk })`로 교체. R3/block → 차단. R2 → `d.approve({ desc, why, level })`.
- `approve` 결과가 `{ ok:false, timeout:true }`(main.js waitUser 10분 [사실: main.js waitUser]) 이면 메시지: `"승인 대기 시간이 지나 안전하게 멈췄습니다. 실행하지 않았습니다."`, 감사 `decision:'timeout'`.
- 행동 도구(open/click/type/select/key)의 zod 입력에 `risk: z.enum(['R0','R1','R2','R3']).optional()` 추가.
- 새 도구 `browser_emergency_stop` (입력 `{ reason?: string }`): `this.d.halt('mcp')` 호출. **재개 도구는 만들지 않는다** (외부 에이전트가 스스로 풀 수 없게).

**D1 — `src/models/router.js`** [사실: record :32, call :41]
- `constructor(getConfig, fetchImpl, { onRecord } = {})`.
- `record(role, model, usage, meta = {})`: 기존 계산·누적 그대로 + `try { this.onRecord?.({ role, model, usage, usd, ...meta }) } catch (_) {}`. 반환값(usd) 그대로.

- `agent:start` 첫 줄: 정지 중이면 `{ error: '비상 정지 중입니다. 위쪽 "재개" 버튼을 누른 뒤 다시 시도해 주세요.' }`.

**D2 — `ui/*`**: 상단 고정 빨간 **"■ 비상 정지"** 버튼(항상 보임), 정지 중이면 붉은 띠 "비상 정지됨 (시각·경로) [재개]". 확인 카드에 `level`이 있으면 "R2" 배지. (디자인은 기존 스타일 따름.)

## 2. 위험 등급 R0~R3 판정표

### 2.1 판정 순서 (위에서부터 처음 걸리는 규칙, 이후 `maxLevel(코드, aiLevel)`)

| 순서 | 조건 (`rule`) | 결과 | 출처 |
|---|---|---|---|
| 1 | `type_text` + 대상 요소 `sensitive` (`sensitive-field`) | R3 + block | 기존 assessRisk [사실] |
| 2 | `type_text` 값이 주민번호 형태 `\d{6}-?[1-4]\d{6}` (`rrn-value`) | R3 + block | 기존 [사실] |
| 3 | `type_text` 값이 카드번호 형태(13~19자리 숫자, 공백·하이픈 허용) (`card-value`) | R3 + block | 신규 [추정], 7장 "카드 칸 입력 차단" |
| 4 | `navigate` 주소가 http/https·도메인 형태가 아님 (`bad-url`) | R3 + block | 기존 [사실] |
| 5 | `click` 대상 이름·종류가 **R3_WORDS** (`r3-word`) | R3 (block) | 7장 R3 |
| 6 | `click` 대상 이름·종류가 **R2_WORDS** (`r2-word`) | R2 | 기존 RISKY_WORDS 중 R3 제외분 |
| 7 | `click` submit + 페이지에 비밀번호 칸 (`login-submit`) | R2 | 기존 [사실] |
| 8 | `type_text` + `press_enter` + 댓글·메시지 칸 (`enter-send`) | R2 | 기존 [사실] |
| 9 | `press_key Enter` + 제목이 댓글·메시지·채팅 (`enter-send`) | R2 | 기존 [사실] |
| 10 | `download` (`download`) | R2 | 7장 |
| 11 | `mail_trash` (`mail-trash`) | `opts.trashLevel` (기본 R2) | 7장 "처음 2주 R2" |
| 12 | `mail_move` (폴더 이동) (`mail-move`) | R1 | 7장 |
| 13 | `navigate, click, type_text, select_option, press_key` 나머지 (`default-r1`) | R1 | 7장 "되돌릴 수 있는 쓰기" [추정: 페이지 이동·입력은 R1로 본다] |
| 14 | `scroll, read_page_text, view_screen, go_back, wait, ask_user, done` 등 조회 (`read-only`) | R0 | 7장 |
| 15 | **표에 없는 이름** (`unknown-action`) | R2 | 안전 쪽 기본값 [추정] |

- `R3_WORDS` (신규): `결제|구매|주문하기|주문 완료|송금|이체|인증서|탈퇴|해지|영구\s?삭제|비밀번호 변경|계정 삭제|pay|purchase|buy now|place order|checkout|transfer|permanently delete|delete account|close account`
- `R2_WORDS`: 기존 `RISKY_WORDS`에서 위 R3 단어를 뺀 나머지 (전송·보내기·발송·제출·신청 완료·삭제·확정·게시·등록하기·올리기·동의·send·submit·delete·remove·confirm·publish·post·unsubscribe) + `주문`(단독). [사실: 기존 목록 agent.js:10]
- **R3는 최소판에서 "항상 차단"**: 실행하지 않고 AI에게 "사용자가 PC에서 직접 하라"고 ask_user로 넘기게 한다. 헌장 4조 "PC 물리 입력으로만"을 가장 단순하게 지키는 방법 [추정]. → 8장 결정 1.
- 영구 삭제 기능은 만들지 않는다(7장) → 해당 이름의 행동 자체가 없음.

### 2.2 "코드가 판정, AI는 올리기만"
- 최종 등급 = `maxLevel(코드 판정, aiLevel)`. aiLevel이 더 낮으면 무시하고 감사 기록에 `aiLevel`만 남긴다.
- block은 AI가 풀 수 없다. AI가 R3로 올리면 block이 된다.
- 외부 내용(웹·메일)에 "이 버튼은 안전하다"가 적혀 있어도 판정은 요소 이름·종류·행동 이름으로만 한다(헌장 6조).

### 2.3 기존 block/confirm 호환·마이그레이션
| 기존 | 새 판정 | 동작 변화 |
|---|---|---|
| `{block}` | R3 + block | 없음 |
| `{confirm}` (RISKY_WORDS 중 결제·구매·송금·이체·탈퇴·해지·transfer 등) | **R3 → 차단** | **변화 있음**: 지금은 "확인 후 실행 가능", 앞으로는 실행 불가(사용자 직접) |
| `{confirm}` (그 밖) | R2 | 없음 (확인 후 실행) |

- `assessRisk`는 `toLegacy`로 같은 모양을 계속 돌려준다 → `mcp-server.js`를 2단계에서 바꾸기 전에도 동작 [추정].

## 4. 비상 정지

### 4.1 세 경로 → 한 함수
```
[전역 단축키 Ctrl+Shift+F12] ─┐
[UI "■ 비상 정지" 버튼] ──────┼─→ killSwitch.halt({source}) ─→ 등록된 정지 함수 전부 실행
[MCP browser_emergency_stop] ─┘        ├ 'tasks'  : 모든 AgentTask.stop() (AbortController 중단, 대기 해제) [사실: agent.js:158]
                                       │            모든 ClaudeCodeTask.stop() (자식 프로세스 kill, 재개 타이머 해제) [사실: cc-engine.js:213]
                                       └ 'pending': main.js pending의 모든 승인·질문 대기 → {cancelled:true}
```
- 전역 단축키는 앱 창이 포커스가 아니어도 동작 [사실: Electron globalShortcut 문서의 기본 동작 — 정확한 Windows 제약은 사용자 PC 수동 시험으로 확인].
- 기본 키 `CommandOrControl+Shift+F12` [추정: Windows 예약 조합(Ctrl+Shift+Esc 등)과 겹치지 않는 것으로 선택]. 다른 프로그램이 이미 쓰고 있으면 `register`가 false → 경고 + UI 버튼으로 대체. 설정 `policy.haltShortcut`으로 바꿀 수 있음.
- MCP 경로는 **정지만 가능, 재개 불가**.

### 4.2 정지 후 상태
- `killSwitch.halted = true` (메모리). 정지 중에는: 새 작업 시작 거부(`agent:start`), MCP 모든 행동 거부(관찰은 허용 [추정: 읽기는 무해]), `guardedAction` 실행 거부.
- 정지된 작업은 **자동으로 이어 하지 않는다**: AgentTask `status:'stopped'`, ClaudeCodeTask `finish(false, '사용자가 작업을 중지했습니다.')` 또는 자식 종료 처리 [사실: cc-engine stop]. 이어 하려면 사용자가 새로 지시.
- 재개: PC 화면의 "재개" 버튼(`source:'ui'`)만. 앱을 다시 켜면 정지 상태는 풀린다(메모리 상태) [추정: 최소판에서 충분, 앱 재시작 자체가 PC 물리 조작].
- 감사 기록: halt·resume 각각 1줄(시각, 경로, 멈춘 작업 수, 오류).
- 메일 분류 실행기(`src/mail/runner.js`)는 아직 앱에 연결돼 있지 않음 [사실: main.js에 mail·runner 참조 없음] → 이번 범위 밖. 연결할 때 `killSwitch.assertRunning()`을 이동 반복문마다 넣는다.

## 5. 감사 기록

- 위치: `%APPDATA%\Jeeves\audit\audit-YYYY-MM-DD.jsonl`, UTF-8, 추가만.
- 기존 `AgentTask.steps`(화면 표시용 메모리)·`jeeves-history.json`(작업 요약 100건)은 그대로 둔다 [사실: main.js saveTaskHistory]. 감사 기록은 별도 파일.
- 1줄 형식:
```json
{"v":1,"ts":"2026-10-07T13:05:12.345+09:00","taskId":12,"source":"agent","kind":"action",
 "action":"click","level":"R2","rule":"r2-word","aiLevel":null,

 "ok":true,"message":"클릭함","why":"\"게시하기\" 버튼은 되돌릴 수 없는 동작일 수 있습니다."}
```
- `kind`: `action` | `halt` | `resume` | `task-start` | `task-end` | `shortcut-fail`
- `source`: `agent` | `jev` | `mcp` | `cc` | `chat` | `ui` | `shortcut` | `system`

- **가림 규칙 (`redact`)** — 시험으로 강제:
  1. `type_text`의 입력값은 **절대 저장 안 함** → `input:{ length: n }`만.
  2. URL은 쿼리·조각 제거(`safeUrl`) — 토큰·세션값 유출 방지.
  3. `label`·`message`·`why`는 각 200자 제한, 그 안의 `\d{6}-?\d{7}`, 13~19자리 숫자, `sk-…`, `Bearer …`, 이메일 주소 형태는 `[가림]`으로 치환.
  4. 메일 행동은 `uid`·폴더 이름·건수만. 보낸 사람·제목·본문 저장 금지.
  5. 작업 목표(`goal`)는 `task-start`에 앞 60자만 + 3번 치환 적용 [추정: 사용자 지시라 비밀이 섞일 수 있음].
- 보관 기간: 최소판은 자동 삭제 없음 → 8장 결정 2.

## 8. 사용자가 결정해야 할 것

### 결정 1 — R3(결제·송금·탈퇴 등) 처리 방식 · **결정 시점: 지금 (담당 A 시작 전)**
- **A안 (추천)**: 항상 차단. 지브스는 멈추고 "PC에서 직접 하세요"라고 요청, 사용자가 직접 누름.
  - 이유: 헌장 4조를 가장 단순·확실하게 지킴, 구현 최소, 오판 시 피해 0. 단점: 지금 Doran 방식에서 가능하던 "확인 후 구매 클릭"이 안 됨.
- B안: PC 전용 확인창 + 사용자가 문구(예: "결제 승인")를 직접 타이핑하면 실행.
  - 빠르지만 구현이 늘고(모바일 승인과 구분·입력 검증), 오판 시 금전 피해 가능.
- 확신도: **높음**. (나중에 B로 바꾸는 것은 risk.js 한 곳 + 확인창 추가로 가능)

### 결정 2 — 감사 기록 보관 기간 · **결정 시점: 구현 중 나중(2단계 끝나기 전까지, 기본 A로 진행)**
- **A안 (추천)**: 자동 삭제 없음(최소판). 필요하면 사용자가 폴더째 삭제.
  - 이유: 삭제 코드가 없어 실수로 기록을 잃을 위험 0, 용량은 하루 수백 KB 수준 [추정].
- B안: 90일 지난 파일 자동 삭제.
  - 개인정보 보관 최소화에 유리하지만 삭제는 되돌릴 수 없음.
- 확신도: **중간**.

## 9. 위험·불확실한 점

1. **동작 변화**: R3 단어 클릭이 "확인 후 실행"에서 "차단"으로 바뀜 → 기존 시험 기대값 수정 가능성 [확인 필요: 2.3 grep].
2. 단어 목록 판정은 오탐·미탐이 있다(예: "주문 내역 보기"가 R2로 잡힘, 영어 아닌 해외 사이트 결제 버튼 미탐). 미탐 대비로 "모르는 행동 = R2", AI 올리기를 둠. P2 인젝션 20종 시험은 이번 범위 밖(다음 단계).
3. `JeevesMcpServer`를 Electron 없이 시험할 수 있는지 [확인 필요] — 안 되면 판정 부분 분리(6장 통합 9번).
4. Electron `globalShortcut`의 Windows 동작(다른 프로그램 점유, 관리자 권한 창 위에서)은 수동 확인 필요.
5. 구독 엔진 비용은 Claude Code가 보고하는 **추정치**(`total_cost_usd`)라 실제 청구가 아님 → `kind:'subscription', billed:false`로 구분 [사실: cc-engine.js:189].
6. `node:sqlite`의 Electron 44 내장 여부 미확인 — JSONL 추천의 이유 중 하나.
7. 메일 실행기(runner.js)를 앱에 연결할 때 비상 정지·위험 판정(mail_move/mail_trash) 연결 필요 [사실: 현재 미연결].
